# 链谈 Agent

面向中小微采购商家的供应商智能接待、分层谈判和筛选系统。

> 核心原则：大模型负责理解和表达，程序负责底线、评分和决策。

## Demo 包含什么

- **多商家（多租户）**：每个商家账号独立存储，商品、供应商、谈判记录按 `merchant_id` 隔离，互不可见。新商家通过注册页自助创建。
- **商家端登录**：支持「账号 + 密码」和「手机号验证码」两种方式一键切换；底部提供「立即注册」入口（账号、密码、确认密码、商家名称、绑定手机号、绑定邮箱，须勾选平台须知）。
- **采购工作台**：编辑目标价、起订量、账期、资质门槛、交期、转人工阈值与七维打分权重，查看供应商分层。
- **AI 实时谈判**：查看对话、底线校验、加权评分、「AI 谈判摘要」（最新条款、评分轨迹）与资质文件核验；高质量候选会停止 AI 自动回复，顶栏铃铛实时提示待接管会话（SSE 推送）。
- **供应商入口**：手机号验证码登录后提交报价、起订量、资质、地区、备货周期和配合方案；勾选资质必须上传至少一份文件，上传后由百度 OCR 自动比对公司名，实时预评估分数与后端同一套公式；可在「我的洽谈会话」中找回历史洽谈。
- **测评实验室**：基于 `json_output/` 测试集回放规则引擎（1500 条报价用例），并对 200 条供应商话术抽样检验 AI 回复的策略命中与越权风险；另含可选的机器学习打分模型（决策树 / 逻辑回归）的在线训练与评估。

## 决策流程

```text
供应商提交条件
        │
        ▼
程序硬性底线校验 ─── 不通过 ──▶ 礼貌结束洽谈
        │通过
        ▼
程序加权评分
        ├── 未达阈值 ──▶ AI 继续议价
        └── 达到阈值 ──▶ 停止 AI 回复 ──▶ 人工接管
```

AI 拉锯过程中，供应商给出新的报价/起订量/交期/账期时，程序会重新执行底线校验并更新评分与分类：评分达到阈值即转人工，触碰硬性底线则立即礼貌结束洽谈。条款抽取由 AI 完成，评分与分类始终由程序计算，AI 不参与决策。

## 本地启动

以下命令以 macOS / Linux 为准（Windows 将 `.venv/bin/` 换成 `.venv\Scripts\`）。

### 1. 后端

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

后端文档：`http://localhost:8000/docs`

### 2. 前端

```bash
cd frontend
npm install
cp .env.example .env.local
npm run dev
```

网页：`http://localhost:3000`

## 大模型与识别服务配置

在 `backend/.env` 中设置（键名模板见 `backend/.env.example`）：

```dotenv
DEEPSEEK_API_KEY=your-key-here
DEEPSEEK_MODEL=deepseek-chat

# 可选：百度智能云 OCR，用于营业执照自动核验
BAIDU_API_KEY=your-baidu-api-key
BAIDU_SECRET_KEY=your-baidu-secret-key
```

未配置 DeepSeek 密钥时，后端会使用可重复演示的本地谈判回复；规则与评分逻辑不受影响。未配置百度密钥时，资质上传直接进入人工核验，其余流程不受影响。密钥不应写入源码或提交到 Git。

## 数据库

本地 Demo 默认使用 SQLite，首次启动会自动建表、写入默认商家和演示商品。切换 PostgreSQL / Supabase 时，只需修改 `backend/.env`：

```dotenv
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/postgres
```

> 说明：SQLite 本地库的加列/回填迁移在启动时自动完成；PostgreSQL 不会自动为已存在的表加列，首次切换到新版本若涉及新增字段（如本次多商家的 `merchant_id`、`email`），需先在数据库手动执行 `ALTER TABLE` 后再启动。

## 使用流程

前后端启动后访问 `http://localhost:3000`，推荐按下面的动线完整走一遍「商家录入 → 供应商报价 → 分层分流 → 转人工」闭环。

### 第 0 步：商家登录 / 注册

1. 首页点「登录」→ 选「采购方」。
2. 用账号密码或手机验证码登录；没有账号点底部「立即注册」，填写账号、密码、确认密码、商家名称、手机号、邮箱并勾选平台须知后提交，注册成功即自动登录。

### 第 1 步：商家录入采购底线（采购工作台 `/dashboard`）

1. 点击「商品库管理」，新增或编辑商品。
2. 填入整套采购底线：目标采购价、硬性价格上限、最高起订量、最长交期、最长账期、转人工分数、必备资质和优先地区，以及七维打分权重（或切换到 ML 打分）。
3. 点击「添加并启用」后，商品会立即出现在供应商入口；停用只隐藏商品，不删除历史记录。

### 第 2 步：供应商上门报价（供应商入口 `/supplier`）

1. 首次进入需用手机号登录：点击「获取验证码」，演示验证码直接显示在页面上。
2. 依次完成四步：选择供货商品 → 填写企业信息 → 填写报价、起订量、账期与配合方案 → 勾选资质并上传至少一份资质文件。右侧「提交前预评估」实时显示与后端同一套公式的预估分数，触线时直接列出未通过项。
3. 上传的营业执照会经百度 OCR 自动识别公司名并与填写企业名比对，自动初筛、人工兜底。
4. 点击「校验并提交方案」，系统立即执行硬性底线校验和加权评分，自动创建供应商档案与谈判会话，并当场返回分类结果。

### 第 3 步：按分层结果分流

| 结果 | 发生什么 |
| --- | --- |
| 淘汰 | 提示条件不匹配（附触线原因），后续消息由系统礼貌收尾，不再打扰商家 |
| AI 拉锯 | 进入谈判页，AI 自动议价、索取可核验信息 |
| 转人工 | AI 自动回复停止，谈判页出现接管提醒，等待商家处理 |

### 第 4 步：商家处理洽谈（实时谈判 `/negotiate`）

1. 左侧是多会话列表（含实时评分），右侧是供应商评分卡、底线校验明细、「AI 谈判摘要」与资质文件人工核验区。
2. 顶栏铃铛实时提示待接管的优质候选会话。
3. 达到转人工条件的会话，点击「接管」后即可人工回复；普通会话可点「恢复 AI 自动谈判」交还 AI。
4. 供应商在对话中给出新条款时，系统自动重新评分并调整分类，商家端通过 SSE 状态流同步看到最新分数。

### 第 5 步：查看经营统计（采购工作台 `/dashboard`）

「今日接待 / AI 自动谈判中 / 优质候选 / 为您节省」四张指标卡由真实记录自动生成，仅统计当前登录商家的数据。

### 第 6 步（可选）：验证引擎质量（测评实验室 `/evaluation`）

- **规则引擎测评**：一键回放全部 1500 条报价用例（不调用大模型），输出总体准确率、混淆矩阵、分组准确率与误判明细。
- **AI 话术抽样测评**：选择话术类型和抽样数量，真实调用大模型生成回复，并用「策略命中 + 越权红线」双闸打分。
- **ML 打分**：在线训练/评估决策树、逻辑回归模型，并返回混淆矩阵、特征重要度等指标。

## 评分模型

默认七维满分（可在商品规则里按商家自定义）：

| 维度 | 默认满分 |
| --- | ---: |
| 价格竞争力 | 30 |
| 起订量 | 15 |
| 资质完整度 | 20 |
| 交期 | 10 |
| 账期 | 10 |
| 区域匹配 | 5 |
| 沟通配合度 | 10 |

硬性规则优先于评分：超过价格上限、起订量上限、交期上限或缺少必备资质时，即使其他项得分较高也会直接淘汰。商品可切换为 `ML` 打分模式（决策树 / 逻辑回归），硬性底线规则仍然生效。

## 演示边界说明

- **商家令牌**：前端与后端都不再携带默认令牌。`NEXT_PUBLIC_ADMIN_TOKEN` 已彻底移除；后端 `ADMIN_TOKEN` 默认值为空（完全禁用该兜底鉴权），公开部署必须留空。
- **多商家隔离**：商家凭登录 token 只能访问自己名下的商品、规则、谈判与资质文件；供应商凭登录手机号只能访问本人会话。供应商入口仍是跨商家的演示目录（按所选商品归属到对应商家）。
- **验证码**：由 `DEMO_MODE` 控制。开启时验证码直接回显给前端（不发送短信），**任意手机号都可被他人登录**，仅适用于公开演示；接入短信服务后须设 `DEMO_MODE=false`。
- **运行环境自检**：把 `ENVIRONMENT` 设为 `prod` 后，启动时会强制校验（`DEMO_MODE` 必须关闭、`DATABASE_URL` 不能是 SQLite、`ADMIN_TOKEN` 必须留空、商家密码不能是默认值、前端地址必须是 https），任一不满足直接拒绝启动。
- **邮箱**：仅做格式 + 唯一性校验，不发送验证邮件。
- **资质识别**：采用「自动初筛 + 人工兜底」机制——百度 OCR 提取执照字段并与填写企业名比对，不一致或无法识别时转人工；图像防伪鉴别是规划中的后续工作。
- **测评与 ML 接口**：会真实调用大模型 / 训练模型，因此全部要求商家登录后才能访问，匿名返回 401。
